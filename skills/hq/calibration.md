## 5 维打分（每项 0–2 分）

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 范围 | 单文件、局部 | 几个文件、一个模块 | 跨模块或跨服务 |
| 模糊度 | 需求明确、有示例 | 有少量需要判断的地方 | 需要自己定方案或找根因 |
| 所需上下文 | 看几处代码就够 | 要理解一个子系统 | 要理解全局架构或历史 |
| 风险 | 易回滚、无副作用 | 影响行为但有测试兜底 | 数据、安全、并发、迁移、公开 API |
| 验证难度 | 一条命令就能判对错 | 需要组合几种验证 | 难以自动验证 |

## 抽象档位

档位描述的是**所需能力**，与宿主无关。

| 档位 | 分数 | 典型任务 | 所需能力 |
|---|---|---|---|
| T0 | 0–1 | 查找汇总、改名、格式化、改文案、简单脚本 | 最快最便宜的模型，低思考深度 |
| T1 | 2–3 | 需求明确的单文件改动、给清晰函数补测试 | 中档模型，低思考深度 |
| T2 | 4–5 | 有明确规格的多文件功能、能复现的普通 bug | 中档模型，中等思考深度 |
| T3 | 6–7 | 跨模块改动、根因不明的 bug、性能或并发问题、安全相关 | 最强模型，中等思考深度 |
| T4 | 8–10 | 架构设计、疑难排障、前面的尝试已经失败 | 最强模型，高思考深度（必要时更高一级） |

最高一级思考深度（如 `max`）不在表内，只在用户明确要求时使用。

## 修正规则

1. **算上失败重来的成本**：预期成本 ≈ 失败概率 ×（低档成本 + 高档成本）+ 成功概率 × 低档成本。
   - 需求明确（模糊度 0）的任务：选最低能胜任的档位；离上一档分数线只差 1 分、或在两档之间犹豫时，按规则 9 上调一步。
   - 需求模糊（模糊度 ≥1）或高风险（风险 2）的任务：直接用够强的档位，争取一次做对；失败一次的重来成本通常超过省下的差价。
2. **看不准就先调研**：模糊度得 2 分、难度判断不了时，先派一个短小的只读调研子会话（T1–T2，目标是给出根因或方案和实际难度），再按调研结论给实现任务打分派发。
3. 只读调研任务最高到 T2。
4. 审核任务比被审任务低一档，但不低于 T1 对应的模型（Claude Code 为 sonnet）。安全和数据相关的审核不降档。
5. **失败与升档**：失败先看是不是任务说明的问题，是就改说明、保持原档位重试一次；还是失败，或子会话报告卡住，就升一档新开子会话从它的分支接着做（交接见 `SKILL.md` 第 7 步“动态调档”）。累计 2 次失败后不再原样重试：换方案（拆小、先调研）或在汇报里列为卡住项，同时继续推进其他任务。
6. **不降档交接**：已经在跑的任务不为省钱换低档会话，重新熟悉项目的开销大于差价。
7. 账户里有其他模型（比如新出的型号）时，按它的能力和价格放进上表合适的档位，并在台账“决策”区注明理由。
8. 用户纠正过的选档偏好，后续任务沿用，并在下次复盘时写进本文件。
9. **拿不准就往上选（用户偏好，2026-11-25；原为只对低成本宿主生效，同日扩展到所有宿主）**：难度判断不确定时，“选低了”失败重来的代价通常大于“选高了”多花的钱，所以**所有宿主**拿不准时都上调一步；额度成本只决定上调多少。
   - **拿不准**指以下任一情况：总分离上一档分数线只差 1 分；模糊度 ≥1；你在两个档位之间犹豫。
   - **成本系数**（默认值；项目 PLAYBOOK 的 `cost_weight` 可以覆盖）：Claude Code 为 `high`；Codex、dsh、Gemini CLI、DeepSeek 后端（经 Claude Code 或 Codex 接入、按 DeepSeek 计费）为 `low`。按**实际计费方**判断：即使宿主接的是 DeepSeek，派到 claude.ai 云端子会话（B 通道）的任务仍按 Claude 额度计，算 `high`。
   - **上调多少**：
     - `low`：**上调一整档**（T0→T1 … T3→T4，模型和思考深度都按新档位）。
     - `high`：**默认只把思考深度上调一级、模型不变**（如 haiku/low→haiku/medium、sonnet/low→sonnet/medium、sonnet/medium→sonnet/high、opus/medium→opus/high）；模糊度 ≥1 或风险 2 时，按规则 1 本就该“直接用够强的档位”，此时**上调一整档**（连模型一起）。
   - **上限**：最多上调一步；不因此动用“必要时更高一级”（如 `xhigh`）或 `max` 思考深度；已在 T4 的不再上调。
   - **不上调的情况**：任务在关键路径上、而且高档明显更慢（例如用户在等一个小改动）；已经遇到频率限制（429 / 限流），这时回到原档并在 notes 记 `rate_limited`。
   - **记录**：上调的任务在 task 记录的 notes 写 `bias:+1(tier)`（整档）或 `bias:+1(effort)`（只上调思考深度）；旧记录里的 `bias:+1(cost_low)` 等同 `bias:+1(tier)`。复盘时按这两种标记分别对比上调和未上调的一次通过率、实际用时、cost_usd；如果上调没有提高一次通过率、只拉长了用时或抬高了花费，就提出收回或缩小适用范围（例如只对 `low` 宿主生效）。

10. **分工路由：辅助执行者（用户偏好，2026-11-25；只在 `assist` 开启时生效）**：主宿主只做难的、重要的；需求明确的中低难度任务交给辅助执行者，再由主宿主审核。**主宿主指运行本插件的会话所用的宿主和模型**（可能是 Claude Code、Codex、Gemini CLI、OpenCode、dsh 等，不一定是 Claude）；下文“留给主宿主”“主宿主接手”都按主宿主自己的档位映射选模型。
   - **与主宿主相同的不算辅助**：profile 用的 CLI 就是主宿主自己的 CLI，或模型与主宿主同厂商、同计费方（例如在 Codex 宿主上 `assist.use` 里有 `codex`），本次跳过它，台账“决策”区记一行 `assist_skip:<profile>:same_as_host`。主宿主想用自家更便宜的模型，按第 3 步的 T0–T2 映射派自己的子代理即可。
   - **派给辅助**，下列条件必须**全部**满足：档位 ≤ `max_tier`（默认 T2，最高只能设 T2）；风险 ≤1；模糊度 0（模糊度 1 只允许 T0/T1）；验证级别为 `doc` 或 `code`，且有一条命令能判对错；不是共享接口、类型、配置这类别的任务依赖的前置任务；不是用于决定后续拆分的调研任务。
   - **留给主宿主**：其余全部，尤其是 T3/T4、`high`/`e2e` 级、架构与接口设计、安全、数据、并发、迁移、根因不明的问题、合并冲突处理、所有审核。
   - **选哪个辅助**：按 `assist.use` 的顺序取第一个**没被停用**的。
   - **停用（熔断）**：本次运行里出现下列任一情况，就停用这个 profile，剩余任务不再派给它：
     1. **不可用**：第 1 步预检不通过（CLI 不在 PATH、未登录、`env_file` 缺失或权限不是 600），或运行中出现 worker 起不来（`state: unknown`、退出码 126/127）、认证失败、限流（429）、额度用完——**立即停用**；
     2. **连续失败 2 次**；
     3. **累计失败**达到 `assist.max_failures`（默认 2，可在 PLAYBOOK 调大，但连续 2 次的规则不变）。
     - “失败”指：退出码非 0；用时超过预计 2 倍；交付缺验证证据；审核结论为 `rework` 或 `failed`（需要主宿主接手）。`pass_with_fixes` 不算失败。
     - 因“不可用”停用时，这个 profile 正在跑的任务立即 stop_worker，改派主宿主；因失败停用时，已在跑的让它跑完、照常审核。
     - **全部停用时**：本次运行剩余任务**全部由主宿主执行**（等同 `--assist off`），按主宿主自己的映射重新选档，不沿用辅助的模型；台账头部 `assist:` 改为 `off（熔断：<profile>:<原因>）`，“决策”区记一行，在下一次汇报里说明一次，**不停下来问用户**。
     - 常驻模式下停用持续到本会话结束，用户重新 `--assist` 才恢复。同一 profile 连续 2 次运行都被停用时，在汇报里建议把它从 `assist.use` 去掉（不自动改 PLAYBOOK）。
   - **与规则 9 的关系**：辅助按 `low` 成本计，拿不准时上调一整档；上调后超过 `max_tier` 就留给主宿主，不派辅助。
   - **关键路径**：任务在关键路径上，而辅助所在通道明显更慢（例如本机资源 `YELLOW`/`RED`、W 槽位已满）时，留给主宿主。
   - **审核**：辅助的产出一律走 `SKILL.md` 第 8 步，审核方是主宿主，**不按规则 4 降档**，至少用主宿主的 T1 映射（Claude Code 为 sonnet）；改动超过约 150 行另派独立审核。
   - **失败回收**：辅助失败（说明本身有问题时先改说明，同一辅助重试一次）→ 不再在辅助上重试，由主宿主高一档从它的分支接手（按规则 5 的交接写法）；限流、CLI 不可用、缺密钥时直接改派主宿主，notes 写 `assist_unavailable:<原因>`，并按上条停用这个 profile。
   - **记录**：task 记录写 `assist: <profile>`；run 记录可选字段 `assist_disabled` 列出本次停用的 profile 和原因；复盘按 metrics 报告“3d 辅助执行者 vs 主宿主”比较同档一次通过率和交接率（≈ 回收率）。辅助某档一次通过率比主宿主同档低 20 个百分点以上，或回收率超过 30%（每组至少 5 个任务）时，提出下调该 profile 的 `max_tier` 或停用它。
