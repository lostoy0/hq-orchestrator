# 子会话任务说明模板

子会话只能看到这份说明，看不到主会话的任何上下文。所以下面每一项都要写全，不要写“如前所述”这类依赖上下文的话。

```
# 任务 <id>：<一句话标题>

## 目标
<要达成什么、为什么要做。1 到 3 句话>

## 背景与入口
- 仓库/目录：<路径或 GitHub URL>，基线分支 <branch>
- 先读这些：<文件路径:行号、文档链接>
- 已经排除的方向：<主会话已知不行的路，避免重复踩坑>

## 范围
- 只允许修改：<文件或目录列表>
- 禁止修改：<共享接口、配置、其他任务的归属文件>
- 不做：<明确不在本任务范围内的事>

## 验收标准
1. <可检验的条件>
2. ...

## 验证（级别：<doc | code | high | e2e>）
<按级别只做该做的，不要跑全量测试；交付前运行并贴出输出末尾 30 行>
- doc（文档、配置）：机械检查，如格式、链接、行数。<命令>
- code（普通代码）：只跑受影响部分的测试、lint、类型检查。<例如 npm test -- path/to/spec --maxWorkers=2>
- high（数据、安全、并发、公开 API）：在 code 级基础上补回归用例，并在 VERIFY 里列出新增用例
- e2e（需要本地环境）：不用跑，合并后由主会话统一跑；在 RISKS 里写明需要覆盖的场景

## 资源限制
- 并行度不超过 <N>（make -j<N> / pytest -n <N> / --maxWorkers=<N>）
- 不要启动常驻服务；如果必须启动，用完立刻关掉
- 预计时长 <X> 分钟。超过 2 倍还没做完，就停下来按“卡住”的方式交付

## 分支与提交
- 在分支 hq/<id> 上提交，提交信息以 "[hq/<id>]" 开头
- <远程子会话：完成后推送到 hq/<id>> <本地 worktree：只提交，不推送>
- 不开 PR，不改其他分支

## 遇到问题时
- 需求有歧义：选最符合目标的解释继续做，在 RISKS 里写明假设。只有猜错会导致大量返工时才提问
- 发现衍生任务：在范围内的小事直接做，不用汇报；超出范围或分量大的不要做，记进 DERIVED
- 遇到以下情况发 CHECKPOINT：衍生出超出范围的任务；实际难度明显高于预期；同一个问题失败 2 次以上。
  内容：发现了什么、建议用什么档位（更强的模型/更深的思考）、你打算继续还是停下
- 卡住（同一问题失败 ≥2 次，或用时超过预计 2 倍）：停下，先提交并推送当前进度，再写交接说明
  （做到哪、试过什么及结果、分支和 sha、建议下一步），状态写 PARTIAL
- 发送方式：<有回报通道：按宿主文档的 message 能力发给主会话 <主会话 id>，不卡住就继续做> <没有回报通道：写在交付格式里（或直接返回，状态写 NEEDS_INPUT 或 PARTIAL），由主会话通过 monitor 获取>
- 回报发不出去（工具调用要等批准、被拒绝）：不要停下来等，继续做；最终结果以交付格式和已推送的分支为准，主会话会通过 monitor 读取
- 禁止为了让测试通过而删除或跳过测试、放宽断言

## 交付格式（最后一条消息必须严格按这个格式）
STATUS: DONE | PARTIAL | NEEDS_INPUT | FAILED
BRANCH: hq/<id> @ <commit sha>
CHANGES: <文件列表与一句话说明>
VERIFY: <验证级别、运行的命令和结果，附输出末尾>
CHECKPOINTS: <发过的检查点，没有就写 none>
DERIVED: <发现的、超出范围没做的衍生任务，没有就写 none>
RISKS: <可能的副作用、没覆盖到的情况>
QUESTIONS: <需要主会话或用户决定的事，没有就写 none>
```

## 写说明的要点
- 能给出文件路径、函数名、错误信息原文，就不要只做描述。
- 只陈述事实，不要把你的猜想当结论交给子会话（“我怀疑是 X”可以写，“问题就是 X”不要写），否则子会话容易只去证实它。
- 审核类子任务只给代码位置和验收标准，不给实现者的报告，这样才能独立判断。
- 验证级别按任务风险写，见 `SKILL.md` 第 8 步的分级表；文档类任务不要要求跑测试。
- **宿主中立**：发给 W 通道或其他宿主 worker 的说明，不能出现 Claude 专有的说法（具体工具名、`send_message`、`_host` 等）。回报一律写成“按宿主文档的 message 能力回报；没有回报通道时，写在交付格式里，由主会话通过 monitor 获取”；需要的具体命令由主会话按目标宿主文档替换好再发。
- 交接任务（升档接手）要写明：上一个会话的分支和 sha、它的交接说明原文、已经排除的方向。
