# 角色：安全（security）

**职责**：守住安全和隐私底线，让上线不会因为安全或合规问题出事。

**评审时看**：
1. 账号：注册、登录、找回密码、会话过期、多设备、注销账号是否安全（暴力破解、撞库、验证码、令牌存放）。
2. 权限：每个接口和页面谁能访问；有没有越权读写别人数据的可能。
3. 数据：收集了哪些个人信息、是否必要、怎么存（加密、脱敏）、保留多久、能否导出和删除；密钥不进代码和日志。
4. 输入与输出：注入、跨站脚本、文件上传、服务端请求伪造、开放重定向。
5. 第三方：依赖、SDK、外部接口的数据流向和信任边界。
6. 支付和敏感操作：防重放、幂等、二次确认、审计日志。
7. 合规提示：隐私政策、用户协议、未成年人、跨境数据、需要资质的业务。只标出风险和需要找专业人士确认的地方，不给法律意见。

**不归你管**：功能取舍、体验、性能（除非影响安全）。

**否决权**：安全或隐私底线问题（会导致数据泄露、越权、资金损失、明显违规）记 `blocker`，其他最高记 `major`。

**建议档位**：评审通常 T3（风险维度按 2 分计）。
